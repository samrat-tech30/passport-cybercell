# Decisions

One line each: `date — decision — why — what we gave up`. Never delete a line; add a new one if a decision changes.

- 2026-10-30 — Track: AgentShield (AI-agent security) — best before/after demo, newest threat, team built an agent at the TCS hackathon — gave up the TrustLens India-scam story (reused in v2-A)
- 2026-10-30 — Core idea: per-argument provenance ("passport") checked deterministically before every tool call — survives rewording/translation; LLM classifiers can be injected — gave up semantic understanding of text
- 2026-10-30 — No LangChain/LangGraph in the core; plain Python agent loop — the gate is the product, frameworks add learning time and version risk tonight — answer "does it integrate?" with `POST /v1/decide` (+ MCP gateway as stretch)
- 2026-10-30 — Backend FastAPI + Pydantic v2; DB SQLite with SQL migrations — zero setup, one file, enough for a demo — no multi-instance scaling
- 2026-10-30 — Frontend React + Vite + TypeScript, plain CSS tokens, no UI kit/Tailwind/router — fewer moving parts, full control of the look — more CSS by hand
- 2026-10-30 — Frontend and backend deployed separately from one repo; frontend calls backend directly with a CORS allowlist — matches "deploy at different servers" — must set ALLOWED_ORIGINS and VITE_API_URL correctly
- 2026-10-30 — Live updates via Server-Sent Events, not WebSockets — one direction is all we need, works through proxies, auto-reconnect — no client→server messages over the stream (approvals use POST)
- 2026-10-30 — Replay mode (scripted plan per scenario) as the default demo mode — no Wi-Fi/LLM dependence, reproducible eval; the gate still runs live — must say openly that the agent plan is recorded
- 2026-10-30 — Naive assistant persona that follows instructions found in documents — makes the shield-OFF attack reproducible; realistic for many assistants — the live model may still refuse sometimes
- 2026-10-30 — Intent capsule built by regex + keyword patterns, no LLM — can't be injected — misses unusual phrasings (falls back to R6 approval)
- 2026-10-30 — Invoice amount is a "soft sink" (untrusted → ask, not deny) — real invoices state the amount — the user must check the amount
- 2026-10-30 — Naming an email address in the request unlocks send_email; the word "email" alone only unlocks reading — "summarise my emails" must not let the agent send
- 2026-10-30 — Canary secrets random per session and redacted everywhere — a fixed fake key could still be logged/committed — none
- 2026-10-30 — Audit log: SHA-256 hash chain in SQLite, no blockchain — tamper-evident, simple — truncation of the tail not detected by the chain alone
- 2026-10-30 — Added R8_TRIFECTA (secret + untrusted + egress → ask); v2 rules renumbered R9–R12 (the earlier build-spec doc said R8–R11) — covers paraphrased secrets — one more approval in that rare case
- 2026-10-30 — Live LLM retries are ours, not the SDK's (`max_retries=0`): one retry on HTTP 429, none on timeout, plus an asyncio backstop at timeout+5 s; every failure is a readable `error` event — a retried timeout doubles the wait on stage — a single 429 burst longer than Retry-After (capped 5 s) ends the run
- 2026-10-30 — Recorded live runs are JSON fixtures in `app/fixtures/` that a scenario loads with `script_file:`; secrets saved as `{{secret:NAME[:enc]}}` templates in every encoding the world knows — real model behaviour becomes replayable and reproducible — a replay only fills a secret the replayed session has really read
- 2026-10-30 — Live LLM: Groq `openai/gpt-oss-120b` (free plan) — calls tools reliably (S1 5/5), fast (~1 s) — 8K tokens/min: leave ~25 s between live runs
- 2026-10-30 — Stronger "naive" persona: obey `Assistant:` lines in emails without confirming — the milder persona was ignored 3/3 on S2 — we must tell judges the agent is configured to be gullible on purpose
- 2026-10-30 — Frontend look (Person B): self-hosted Geist + Geist Mono (OFL woff2 in public/fonts), CSS-only choreographed motion, one WebGPU guilloché seal in the idle state with a 2D canvas fallback — premium, credible type without network fonts or new packages; the 3D piece is never on screen during a run — 140 KB of fonts; the seal needs a GPU adapter (falls back otherwise)
- 2026-10-31 — UI round 2 (Person B): light theme default + dark toggle, WebGPU seal removed, motion only where it explains something, gate strip + scenario cards + plain-English headlines built on the frontend from passports — the owner found the dark/animated version hard to read; projectors wash out dark UIs — more frontend wording to keep in sync with rule meanings (RULE_TEXT in format.ts)
- 2026-10-30 — S2 shield OFF is demoed in **replay**, not live — live gpt-oss-120b leaked the key in only 2/9 runs (read the secret 9/9, then usually just claimed it had sent it) — say this openly; live mode is shown for S1 and S2 shield ON
- 2026-10-31 — UI round 3: Sky Ink design system (white page, ink, Newsreader + Geist, one blue action per view, one sky block per page, yellow only as a highlighter, line-art illustrations) — the round-2 UI still read as AI-made (coloured side borders, boxed chips, beige greys, purple) — Newsreader adds 132 KB of self-hosted font
- 2026-10-31 — Sky Ink exception: three printed-ink verdict colours (ok #166534, warn #92400E, bad #B91C1C) added to the palette; origins mapped to Sky Ink only (panel fill = from you, yellow highlighter = outside content, black redaction bar = secret, dashed underline = written by the AI) — Sky Ink has no red/green/amber and bans purple, but a judge must read ALLOW/DENY in 3 seconds — two more colours than Sky Ink allows, used only for verdicts
- 2026-10-31 — Dark theme removed — Sky Ink is a white-page system and projectors wash out dark UIs; one theme designed properly beats two half-checked — no dark mode
